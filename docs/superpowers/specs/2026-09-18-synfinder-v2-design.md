# SynFinder v2 — design

**Date:** 2026-09-18
**Status:** approved design
**Author:** Chang Sun (with Claude)
**Builds on:** `2026-09-18-synfinder-design.md` (v1, shipped)

## 1. What v2 adds

Three subsystems, built in this order because each makes the next worth having:

1. **Output previews** — every method shows what shape of data it emits.
2. **Dataset registry** — ready-made synthetic datasets are offered *before*
   methods, so nobody trains a model they did not need to train.
3. **Community submission** — anyone can contribute a method or dataset by
   pull request, with CI enforcing the schema and a review gate protecting the
   catalog's judgement.

## 2. The governing tension

v1's value is that the catalog encodes hard-won judgement: every entry carries
an honest caveat, including caveats the method's own authors would not write.
Open submission pulls against this. The median unreviewed submission is a
method author describing their own method, and method authors do not write
"cite it; do not deploy it" about their own work.

**The review gate is therefore the design, not a detail.** Growth is the goal;
credibility is the constraint. Every decision below resolves in favour of the
constraint.

## 3. Output previews

### 3.1 Schema

A new optional block on `Method`:

```yaml
output_preview:
  format: tabular_csv
  note: One row per patient; diagnosis codes are ICD-10.
  preview: |
    patient_id,age,sex,bmi,hba1c,diagnosis
    p0001,54,F,27.3,6.1,E11.9
```

`format` is drawn from a new taxonomy key `preview_formats`:
`tabular_csv`, `event_sequence`, `genomic_matrix`, `image_spec`, `text`,
`graph_edgelist`.

### 3.2 The honesty rule

Previews are **illustrative of output format, not generated by the method**.
Presenting a hand-written sample as real model output would be a lie told by a
tool whose subject is synthetic data honesty.

The disclaimer is rendered by code, above every preview, in the CLI, the
report and the app. It is **not** a YAML field, so no contributor can omit it
and no entry can override it.

### 3.3 Modality rules

A CSV snippet is meaningless for most of the catalog's data types:

| format | shows |
|---|---|
| `tabular_csv` | header plus two or three rows |
| `event_sequence` | a patient with nested visits and codes |
| `genomic_matrix` | a small variant-by-sample genotype matrix |
| `graph_edgelist` | a few edges with attributes |
| `text` | a short excerpt in the register the method produces |
| `image_spec` | **a written specification, never a picture** |

`image_spec` exists because a fabricated brain MRI would be indistinguishable
from a real claim. It carries dimensions, modality and file format —
`256x256x256 single-channel T1-weighted NIfTI volume` — which is the thing a
researcher actually needs to know.

## 4. Dataset registry

### 4.1 Schema

`Dataset` grows the fields matching requires:

- `domains: list[str]` (replaces the single `domain`)
- `data_types: list[str]` (replaces the single `data_type`)
- `purposes: list[str]` — what the dataset is fit for
- `n_records: str` — human-readable scale
- `formal_dp: bool` and optional `dp_mechanism`
- `generated_by: str | None` — a method id, validated against the catalog
- `access_conditions`, `license`, `realism_caveats` (>=1), `links` — as v1

`realism_caveats` keeps its minimum of one, for the same reason methods must
carry a caveat: an entry with no stated limitation has not been reviewed.

### 4.2 Matching and precedence

`match_datasets(datasets, intake) -> list[Dataset]` filters on domain, data
type and purpose. It runs **before** ranking.

When it returns anything, the report and the app open with:

> **You may not need to generate anything.** These datasets already exist and
> match what you described.

followed by the methods as usual. Leading with the registry is the point: the
waste this prevents is training a model that did not need training.

### 4.3 Browsing

A dataset browse view, filterable by domain, data type and licence, reachable
without going through the intake — in the app as a second tab, on the command
line as `synfinder datasets`.

## 5. Community submission

### 5.1 Two doors, one destination

Both end in a pull request adding one YAML file.

- **`synfinder new method` / `synfinder new dataset`** — an interactive prompt
  that constrains every controlled answer to the taxonomy and writes a valid
  file. A contributor cannot produce an invalid entry.
- **A GitHub Issue Form** with the same fields as dropdowns, for contributors
  who will not use git. A maintainer converts an accepted issue into a PR.

### 5.2 CI is the safety mechanism

A GitHub Actions workflow runs the full test suite on every pull request:
schema validation, taxonomy conformance, YAML parse, caveats non-empty,
scale-bounds-need-evidence, and the golden scenarios. A submission that breaks
any of these cannot merge unnoticed.

The golden scenarios matter most here: they are how a contributor's new entry
is caught changing an answer that was previously correct.

### 5.3 Governance in CONTRIBUTING.md

Three rules, stated plainly:

1. **Declare authorship.** If you wrote the method, say so in the pull
   request. This is not disqualifying; concealing it is.
2. **Caveats must name real failure modes.** An entry whose caveats are
   marketing gets rejected. "Requires tuning" is not a caveat; "high-cardinality
   categoricals destabilise training and rare categories are dropped" is.
3. **Claims need sources.** Scale bounds require `evidence` (already enforced
   by the schema). Release dates come from the repository, never from memory.

A maintainer review checklist accompanies these, covering the fields where a
wrong value silently changes recommendations: `data_types`, `formal_dp`,
`compute`, `purposes`, `requires_no_source_data`.

## 6. CLI restructure

The command becomes subcommand-based:

| command | does |
|---|---|
| `synfinder find --domain … --data-type …` | today's behaviour |
| `synfinder datasets [--domain …] [--data-type …]` | browse the registry |
| `synfinder new method` / `new dataset` | interactive contribution |

**This breaks `synfinder --domain …`.** The tool is one day old with no
external users; the cost of the break will never be lower than now.

## 7. Testing

- Preview format values conform to the taxonomy; `image_spec` entries are
  asserted to contain no image data.
- The disclaimer appears in rendered output for every method carrying a
  preview — asserted at the renderer, so it cannot regress.
- `match_datasets` returns datasets before methods are ranked, and a matching
  dataset appears above the shortlist in the report.
- `generated_by` on a dataset resolves to a real method id.
- Each new CLI subcommand has a smoke test.
- Golden scenarios extend to cover a dataset-first result.

## 8. Out of scope

Hosting datasets (the registry points, it does not store); a web backend or
database; user accounts; automated conversion of issue forms to pull requests;
real generated samples per method — deliberately deferred, and the reason
previews are labelled illustrative.
